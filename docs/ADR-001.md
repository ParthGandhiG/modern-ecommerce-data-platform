# ADR-001: Lakehouse + Warehouse Split

## Decision
Use object storage + Delta for scalable engineering transformations and a warehouse for curated analytical consumption.

## Rationale
This separates high-volume ingestion/processing from business-facing SQL models and BI workloads. It also allows Spark and dbt to be optimized for their respective responsibilities.

## Alternatives
A warehouse-only architecture is simpler for modest volumes, while a lake-only architecture can reduce duplication but often increases BI governance complexity. The chosen design demonstrates both engineering and analytics concerns.
